### `scripts/insert-drizzle-migrations.sql` (SQL, idempotent stamp)

**Primary analog:** `apps/backend/src/db/migration-prod.sql` (transactional batch pattern in the repo — referenced in `.planning` as the canonical idempotent SQL).
**Secondary analog:** `apps/backend/drizzle/0003_add_columna_inv_articulos.sql:1-4` (header comment style + `IF NOT EXISTS` pattern).

**Idempotent stamp pattern** (synthesized — apply per row, all wrapped in single `BEGIN; … COMMIT;`):

```sql
-- Phase 38 D-03: stamp 0000-0006 entries into drizzle.__drizzle_migrations.
-- Idempotent: each INSERT guarded by NOT EXISTS so re-running this script is safe.
-- DOES NOT execute any of the 0000-0006 SQL files — pure metadata stamp.
-- Run via: docker exec -i postgres psql -U sanchez -d erp_sanchez < scripts/insert-drizzle-migrations.sql

BEGIN;

-- 0000_open_anita_blake (computed hash: <recompute at runtime via sha256sum>)
INSERT INTO drizzle.__drizzle_migrations (hash, created_at)
SELECT '<sha256-of-0000-sql>', 1772422128557
WHERE NOT EXISTS (
  SELECT 1 FROM drizzle.__drizzle_migrations WHERE hash = '<sha256-of-0000-sql>'
);

-- (repeat for 0001-0006 with their respective hashes and journal `when` timestamps)

COMMIT;
```

**Pattern decisions (anchored in CONTEXT.md + research):**

- **Schema-qualified everywhere**: `drizzle.__drizzle_migrations` (research pitfall 1 — failing without `drizzle.` prefix).
- **`NOT EXISTS` guard, not `ON CONFLICT`**: the table has no UNIQUE constraint on `hash` to back `ON CONFLICT (hash)` — verify before assuming. Research §3 confirms the table only requires `(hash, created_at)` columns; the PK is `id` (serial).
- **`created_at` = `journal.entries[i].when`** (research §1 finding — Drizzle skips by `created_at < folderMillis`, not by hash). Reuse the exact integer-millis from `_journal.json`.
- **Hash placeholder**: do NOT hardcode hashes — the audit script computes them and passes them as bind values, OR the SQL file is generated by the audit script as a derived artifact. Research pitfall 4 (line endings) means the planner must compute hashes on the same machine the SQL is generated on.

### Idempotent SQL against production

**Source:** `apps/backend/drizzle/0003_add_columna_inv_articulos.sql:1-4` + `apps/backend/src/db/migration-prod.sql` (referenced as canonical idempotent batch).
