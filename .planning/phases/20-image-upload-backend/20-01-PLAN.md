**Step 2: Create UploadImagenDto** (`dto/upload-imagen.dto.ts`)

- `tipo`: validated with `@IsIn(['etiqueta', 'producto'])`, type `'etiqueta' | 'producto'`
- `slot`: `@Transform(({ value }) => parseInt(value, 10))` + `@IsInt()` + `@Min(1)` + `@Max(6)` — CRITICAL: FormData sends strings, the Transform decorator is mandatory or @IsInt() will fail on "1"
- Import from `class-validator` and `class-transformer`

**Step 3: Create ArticulosImagenesService** (`articulos-imagenes.service.ts`)

- `@Injectable()`, inject `DrizzleService` (same pattern as `ArticulosService`)
- Private helper `sanitizeCodigo(codigo: string): string` — normalize NFD, strip diacritics, replace non-alphanum with `_`, collapse consecutive `_`, trim leading/trailing `_`, toUpperCase. Example: "ABC/123 N" -> "ABC_123_N"
- Private helper `buildFileName(codigo: string, slot: number, size: 'thumb' | 'detail'): string` — returns `${sanitizeCodigo(codigo)}_${slot}_${size}.webp`
- Private helper `getOutputDir(tipo: 'etiqueta' | 'producto'): string` — returns `join(process.cwd(), 'uploads', 'articulos', tipo === 'etiqueta' ? 'etiquetas' : 'productos')`
- Private helper `getDbField(tipo): 'imagenesProducto' | 'imagenesEtiqueta'` — maps tipo to schema field name
- `async uploadImagen(codigo: string, buffer: Buffer, dto: UploadImagenDto)`:
  1. Verify articulo exists via `this.drizzle.db.select().from(articulos).where(eq(articulos.codigo, codigo))` — throw NotFoundException if not found
  2. Validate slot range: etiqueta max 3, producto max 6 — throw BadRequestException if exceeded
  3. Process with sharp:
     - Thumbnail: `sharp(buffer).resize(200, 200, { fit: 'cover', position: 'centre' }).webp({ quality: 80 }).toBuffer()` — sharp(buffer) implicitly validates magic bytes; if buffer is not a real image, sharp throws (this IS the magic bytes validation)
     - Detail: `sharp(buffer).resize(1000, 1000, { fit: 'inside', withoutEnlargement: true }).webp({ quality: 80 }).toBuffer()`
  4. Write files: `mkdir(outputDir, { recursive: true })` + `writeFile` for both thumb and detail
  5. Build URL: `/api/uploads/articulos/${tipo}s/${fileName}` (note the plural `s` — directories are `etiquetas/` and `productos/`)
  6. Update DB: read current array, extend with nulls if needed, set `arr[slot - 1] = detailUrl` (only detail URL stored; thumb derived by convention replacing `_detail.webp` with `_thumb.webp`)
  7. Use `this.drizzle.db.update(articulos).set({ [dbField]: arr, updatedAt: new Date() }).where(eq(articulos.codigo, codigo)).returning()` — return the full updated articulo
  8. Wrap sharp processing in try/catch — if sharp throws, return 400 with "Archivo no es una imagen valida"
- `async deleteImagen(codigo: string, tipo, slot)`:
  1. Verify articulo exists — throw NotFoundException if not
  2. Build file paths for thumb and detail
  3. `unlink` both files, wrapped in try/catch (ignore ENOENT — idempotent delete)
  4. Update DB: set `arr[slot - 1] = null`, update with Drizzle, return updated articulo
- Import `sharp` as default import: `import sharp from 'sharp'` (NOT `import * as sharp`)
- Import `writeFile, mkdir, unlink` from `fs/promises`, `join` from `path`
- Import `eq` from `drizzle-orm`, `articulos` from schema

**Step 1: Update HttpExceptionFilter** to also catch MulterError
- Add a second `@Catch` or create a combined filter. Recommended approach: change `@Catch(HttpException)` to `@Catch()` (catch all) and handle both `HttpException` and `MulterError` inside, OR add a separate `@Catch(MulterError)` class. Simplest: modify the existing filter to handle both:
  ```typescript
  import { MulterError } from 'multer'
  ```
  - If `exception instanceof MulterError`: return 400 with message "Archivo demasiado grande (max 5MB)" for `LIMIT_FILE_SIZE`, or the error message for other Multer errors
  - If `exception instanceof HttpException`: existing logic (unchanged)
  - Change the `@Catch()` decorator to catch both: `@Catch(HttpException, MulterError)` — NOTE: this requires importing `MulterError` from `'multer'` (available transitively via @nestjs/platform-express)
  - The filter's `catch` method param type becomes `HttpException | MulterError`
  - Use instanceof checks to differentiate

**Step 2: Create ArticulosImagenesController** (`articulos-imagenes.controller.ts`)

- `@Controller('articulos')` — same route prefix as existing ArticulosController (NestJS merges routes from controllers in same module)
- Inject `ArticulosImagenesService`
- POST endpoint `@Post(':codigo/imagenes')`:
  - `@UseGuards(RolesGuard)` + `@Roles('admin')`
  - `@UseInterceptors(FileInterceptor('file', { storage: memoryStorage(), limits: { fileSize: 5 * 1024 * 1024 }, fileFilter }))` where fileFilter checks `['image/jpeg', 'image/png', 'image/webp']` and throws BadRequestException for invalid MIME
  - Params: `@Param('codigo') codigo: string`, `@UploadedFile() file: Express.Multer.File`, `@Body() dto: UploadImagenDto`
  - Body: `if (!file) throw new BadRequestException('Archivo requerido')` then delegate to service
  - Imports: `FileInterceptor` from `@nestjs/platform-express`, `memoryStorage` from `multer`
- DELETE endpoint `@Delete(':codigo/imagenes/:tipo/:slot')`:
  - `@UseGuards(RolesGuard)` + `@Roles('admin')`
  - Params: `@Param('codigo') codigo`, `@Param('tipo') tipo: string`, `@Param('slot', ParseIntPipe) slot: number`
  - Delegate to service with tipo cast: `tipo as 'etiqueta' | 'producto'`
